# 执行与恢复

用于工具接口、上下文、持久化、人审与外部动作。只读短任务可以沿用宿主现有运行能力。

## 工具与上下文

为当前任务暴露必要能力，避免用途重叠与大量无关结果。接口至少明确用途、输入、成功结果、错误及前置条件；写操作还要有目标、操作身份和回执。

- 已知用户身份、租户与权限由程序绑定和验证，不让模型随意构造。
- 结构化参数解决格式约束，业务语义仍需运行时校验。
- 返回可导航、可分页的高信号结果；保留原始证据引用。
- 外部文本按数据处理，不允许其自行变成高优先级指令或新增授权。
- 状态保存已验证事实、假设、计划、产物位置和未解决项；会话摘要不能取代原始证据。

## 最小可恢复状态

依据宿主现有存储设计，不强制新增数据库。需要跨进程或跨会话恢复时，至少能够找到：

| 信息 | 目的 |
| --- | --- |
| 任务身份与流程版本 | 恢复同一任务并解释执行规则 |
| 当前步骤与已完成项 | 避免把未验证工作当成完成 |
| 事实、产物及证据引用 | 继续工作前核验已有成果 |
| 外部操作身份、参数和回执 | 去重、对账与确认动作终态 |
| 等待原因与审批决定 | 区分等待输入、等待批准和执行失败 |
| 剩余预算与停止原因 | 恢复后继续受同一任务约束 |

生命周期可表示为运行中、等待输入 / 审批、已完成、失败或取消。等待是可恢复状态；失败与部分完成不得标为完整成功。

## 错误处理

| 情况 | 处理方式 |
| --- | --- |
| 暂时网络失败、限流，且可安全重试 | 退避并受总预算约束，遵守服务端重试提示 |
| 参数、解析或工具选择错误 | 根据明确错误修正输入，避免原样重复 |
| 缺失关键输入 | 保存当前成果并请求必要信息 |
| 权限不足、动作超出范围 | 停止该动作，按任务权限处理，不能通过换工具绕过 |
| 请求超时，外部写入可能已成功 | 标记结果未知，先核验远端状态与回执 |
| 未知程序异常 | 保存诊断证据，修复或升级处理，不能伪装成功 |

避免客户端、工具和编排层分别独立重试，导致总次数相乘。为当前任务约定次数、耗时或成本上限；相同失败没有新信息时停止该路径。

## 副作用、幂等与人工决定

一次业务操作使用稳定操作身份，传给支持去重的下游。身份应贯穿恢复与重试；若整个流程重新发起仍代表同一业务操作，不能仅以新 run ID 代替它。

下游不支持幂等时，先查业务状态与操作回执。结果仍未知时，暂停该写路径并交付待对账信息；不要承诺 exactly-once，也不要仅凭本地 checkpoint 缺失再次付款、发信或建单。

需要审批时展示具体目标和参数，在动作执行前暂停；保存决定并恢复同一任务。已有授权覆盖的动作按原范围继续，只有操作实质变化或授权缺失时才重新请求决定。

## 运行时语义必须核对

- LangGraph interrupt 恢复会重跑节点开头部分；中断前动作需要幂等，或拆到审批后的独立节点。
- LangGraph 调试 replay 会重执行所选 checkpoint 之后的节点，包含模型和 API 调用。
- Temporal Workflow 需要可确定性回放；LLM 与外部访问放入 Activity。已记录 Activity 结果在历史回放中复用，但 Activity 重试仍可能重复外部动作。
- 其他框架也分别核对正常恢复、故障重试、人工 resume 与调试 replay，不能套用另一框架的保证。

这些是运行时相关机制；具体实现前按当前版本查官方说明，来源见 [sources.md](sources.md)。

## 恢复验收

只在隔离测试环境模拟与本次改动相关的失败：

1. 模型已产出，尚未保存状态时进程退出。
2. 外部写入成功，确认或 checkpoint 落盘前进程退出。
3. 并行分支部分失败，成功分支结果需要保留。
4. 审批等待跨进程恢复；拒绝后不能执行原动作。
5. 任务运行期间代码或 prompt 版本变化。

核验产物、远端动作次数、预算与运行状态。记录实测结果；不在生产系统通过真实扣款、发信等动作制造故障。
