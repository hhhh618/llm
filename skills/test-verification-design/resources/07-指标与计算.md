# 指标与计算

**来源：** 《GJB 2547B-2024 装备测试性工作通用要求》（中央军委装备发展部，2024-07-05）。
**对应PDF：** 第6~10、24、33~35、48~49、57页；各段分别注明正文或资料性附录。
**提取日期：** 2026-10-15。
**说明：** 定义与评估约束来自正文，预计及计数公式来自资料性附录；脚本输入需经确认，结果不自动判合格。

本资源用于确定统计口径、整理计算输入和解释结果。`scripts/metrics.py` 只用 Python 标准库在本机读取 JSON；不调用外部接口，不修改原始记录，不直接给出合格结论。脚本使用经人工确认的数据；它不会自动判定责任故障、虚警或隔离是否成功。

## 1. 先确定对象与计算口径

来源：正文3.1（PDF第6-7页，印刷第1-2页）、4.6.2（PDF第10页，印刷第5页）。

每次计算先记录产品层次与技术状态、运行条件和观察期间、检测手段、责任故障范围、严重故障判据、可更换单元层次、隔离模糊度以及时间单位。缺少这些信息时，可整理数据或演示公式，但不能据此判定指标达标。

正文4.6.2列出的定量参数包括：故障检测率（FDR）、严重故障检测率（CFDR）、故障隔离率（FIR）、虚警率（FAR）、平均虚警间隔时间（MTBFA）、平均严重故障虚警间隔时间（MTBFACF）、平均诊断时间（MTTD）、平均故障检测时间（MFDT）和平均故障隔离时间（MFIT）。FAR、MTBFA、MTBFACF不能相互直接替换；检测时间、隔离时间也不能在未确认起止事件时与诊断时间混用。

必须区分两类数据：

| 用途 | 数据基准 | 可得到的结果 |
| --- | --- | --- |
| 测试性预计 | 故障模式、故障率、设计检测能力及隔离分类 | 按故障率加权的预计值 |
| 运行/试验数据评估 | 经确认的责任故障、检出、隔离、报警、虚警次数及运行时间 | 点估计；按规定方案另算置信限 |

不能把故障模式数量当故障率加权结果，也不能把预计故障率与实际故障次数混在同一分子、分母中。相同模式可能在实际运行中多次发生；样本次数和模式条数不是同一概念。

## 2. 按故障率加权的预计（资料性附录）

来源：附录A.6.2.4.3-A.6.2.4.4（PDF第48-49页，印刷第43-44页）；附录A是资料性附录。需要说明预计方法、数据来源、产品层次与经确认的测试范围。

以同一单位表示全部故障模式的故障率。令 `λ` 为总故障率，`λ_d` 为能够检测的故障模式故障率合计：

`FDR比例 = λ_d / λ`。

该比例对应式（A.1）；式（A.3）按相关性模型对可检测故障集合求和，并把结果写为百分数。脚本同时输出 `ratio` 和 `percent=ratio×100`，避免将0.95和95混用。

对于规定的可更换单元层次和隔离模糊度 `L`，令 `λ_IL` 为可隔离到模糊度不大于L的故障模式故障率合计：

`FIR比例 = λ_IL / λ_d`。

这对应式（A.4）；分母是**已检出故障率合计**，而不是总故障率。`L=1` 表示按约定单元口径的唯一性隔离；L表示隔离候选单元的模糊度，不能用故障模式编号数代替。式（A.5）按隔离模糊组汇总故障率；同一故障模式不能重复计入不同组。

原扫描式（A.1）、（A.4）不含 `×100%`，式（A.3）、（A.6）含 `×100%`。资源保留这一原文写法差异，实际输入和输出统一明确比例/百分数。式（A.6）含复杂量词、故障测试集和可更换单元条件，不能根据破损OCR直接实现；脚本没有实现该式的自动隔离判定。

脚本的加权FIR只接受已经确认的故障模式隔离分类。对每个可检测模式，明确提供 `isolation_ambiguity`：正整数表示按指定单元层次确认的候选单元数；`null` 表示已经确认不能按该口径隔离。缺少该字段意味着分类未知，脚本拒绝默认将其当作未隔离。用 `isolation_scope_confirmed=true` 声明这些分类和 `isolation_unit`、`max_ambiguity` 的口径一致；该字段记录数据前提。

## 3. 按次数评估的点估计（资料性附录）

来源：附录A.7.2.3.8-A.7.2.3.10（PDF第57页，印刷第52页），以及严重故障检测率定义3.1.3（PDF第7页，印刷第2页）。以下是按定义整理的点估计表达；不能代替正文8.3.2.7要求的置信限评估。

| 指标 | 分子 | 分母 | 关键口径 |
| --- | --- | --- | --- |
| FDR | 规定手段正确检出并报警的责任故障次数 | 责任故障总次数 | 原始故障记录经确认，检测手段范围一致 |
| CFDR | 正确检出的严重故障次数 | 严重故障总次数 | 严重故障判据一致，不能以全部故障作分母 |
| FIR | 报警信息满足规定隔离模糊度的故障次数 | 正确检出的故障次数 | 隔离单元层次与模糊度明确；不能以全部责任故障作分母 |
| FAR | 经确认实际未发生故障的报警次数 | 报警总次数 | 虚警识别依据与报警去重规则一致 |

全部比率同时给出比例与百分数。数据应满足：检出次数≤责任故障次数；隔离成功次数≤检出次数；虚警次数≤报警次数；严重故障与检出的严重故障次数≤相应总数。检测报警与虚警报警未必能与故障次数建立逐条的一一关系，脚本不会擅自要求“检出次数＋虚警次数＝报警次数”。

同一责任故障总体内，设总次数为 N、严重故障次数为 C、检出次数为 D、检出的严重故障次数为 X，还必须满足 `max(0, C + D - N) ≤ X ≤ min(C, D)`。这是集合计数的一致性校验，不是标准新增门限。例如 N=10、C=8、D=8 时 X 至少为6，填5应拒绝计算。各数来自不同总体或观察期间时，不得合并套用该式。

若数据方案已经确认每次正确检测对应一条独立报警，可设置 `alarm_fault_mapping="one_alarm_per_detected_fault"`，脚本追加校验“正确检测次数＋虚警次数≤报警总次数”；未分类报警仍可保留，不要求相等。若一条报警可能涵盖多个责任故障，应先核对事件映射，不使用该字段强行建立一一关系。

间歇故障、不能复现（CND）或重测合格（RTOK）需要结合原始记录判断；不能因为不能复现就自动归为虚警（另见资料性A.4.2.1.10.2有关说明，PDF第34页，印刷第29页）。重复报警、责任故障范围、补充故障注入试验的纳入方式应由评估方案明确。

## 4. 平均时间

来源：3.1.2（PDF第6页，印刷第1页）、3.1.4-3.1.5（PDF第7页，印刷第2页）；平均虚警间隔时间评估的数据要求另见A.7.2.3.9（PDF第57页，印刷第52页）。

| 指标 | 定义整理的计算式 | 时间输入 |
| --- | --- | --- |
| MTTD | 故障诊断累计用时 / 故障诊断总次数 | 各次故障诊断所用时间之和 |
| MTBFA | 规定条件下产品累计运行时间 / 确认虚警总次数 | 产品运行总时间，不能用诊断用时替代 |
| MTBFACF | 规定条件下产品累计运行时间 / 显示或报告出现严重故障的确认虚警总次数 | 运行条件与严重故障报警类别一致 |

脚本要求 `time_unit` 明确为 `s`、`min` 或 `h`；输入先换算到统一单位，输出保留该单位。脚本不自动混合不同单位、不自动累加存在重叠的运行时段，也不自行确定诊断的开始/结束事件。MFDT和MFIT需要另按项目确认的定义、观察起止事件和记录方法处理，本脚本不推断其计算规则。

若观察期间虚警次数为零，不能通过除零把MTBFA/MTBFACF写成无穷大或宣称达标。应保留观察时间与“零虚警”事实，再按经确认的统计方案处理相应置信限；脚本返回明确错误。任何指标分母为零也不返回0或100%作为替代值。

## 5. 置信限、样本量和合格判据

来源：正文8.3.2.7（PDF第24页，印刷第19页）、资料性A.7.2.3.10-A.7.2.3.11（PDF第57页，印刷第52页），验证要求见正文4.7（PDF第10页，印刷第5页）。

正文规定：评估定量要求达标时，FDR、FIR和MTBFA一般采用单侧置信下限；FAR一般采用单侧置信上限。资料性附录说明，FDR/FIR要求值为100%时可以采用点估计，其他时间类参数可采用点估计；该说明不能用来取消合同或试验方案另有规定的统计要求。

置信水平、统计分布/模型、试验方案、纳入/剔除规则和目标阈值不齐全时，不臆定常用置信水平，不自行宣称结果合格。本脚本只输出点估计或预计，输出中的 `confidence_limits=null` 与 `conformity="未判定"` 必须保留。

最小样本量依约定试验方案确定。附录A.7.2.3.11指出，当相关比率评估的样本量低于最小样本量时，具备条件的应补充必要的故障注入试验；不具备条件应注明低于最小样本量。不能把“成功次数等于总次数”当成统计充分的证明。

## 6. 示例阈值与原文疑义

来源：资料性表A.3（PDF第33页，印刷第28页）、A.4.2.1.10.3(a)（PDF第35页，印刷第30页）。

表A.3标题明确为“测试性定量要求示例”。其中不同范围的检测率、隔离率、时间等示例值，不能作为所有装备统一验收门限；实际阈值来自经确认的测试性要求、合同与剪裁结果。计算脚本不预设阈值。

A.4.2.1.10.3(a)原扫描写“利用工作项目302规定的程序和方法分配”；正文中302为测试性模型建立、303为测试性分配，存在交叉引用疑义。保留原文并标注疑义，不能把未经授权的改写当作标准勘误。

## 7. 脚本使用与输入示例

运行方式：在技能目录执行 `python3 scripts/metrics.py --input 数据.json`；也可将JSON传入标准输入。成功返回JSON且退出码0；数据缺失、零分母、负数、非有限数或不一致计数返回 `status="invalid_input"` 和中文错误说明，退出码2。JSON重复键被拒绝，避免后一个值静默覆盖前一个值。

<!-- PDF第48页 -->
### 7.1 故障率加权预计FDR/FIR

```json
{
  "mode": "weighted_prediction",
  "metrics": ["FDR", "FIR"],
  "failure_rate_unit": "1/h",
  "isolation_unit": "现场可更换单元 LRU",
  "max_ambiguity": 1,
  "isolation_scope_confirmed": true,
  "faults": [
    {"id": "f1", "failure_rate": 0.002, "detected": true, "isolation_ambiguity": 1},
    {"id": "f2", "failure_rate": 0.001, "detected": true, "isolation_ambiguity": 2},
    {"id": "f3", "failure_rate": 0.001, "detected": false}
  ]
}
```

结果：FDR为0.75/75%；FIR为约0.6667/66.67%。FIR分母为0.003/h，不能错误地用总故障率0.004/h。

<!-- PDF第57页 -->
### 7.2 经确认次数的评估点估计

```json
{
  "mode": "count_assessment",
  "metrics": ["FDR", "FIR", "FAR"],
  "alarm_fault_mapping": "one_alarm_per_detected_fault",
  "isolation_unit": "现场可更换单元 LRU",
  "max_ambiguity": 1,
  "isolation_scope_confirmed": true,
  "counts": {"faults": 100, "detected": 90, "isolated": 81, "alarms": 110, "false_alarms": 11}
}
```

结果：FDR=90%，FIR=90%，FAR=10%，均仅为点估计。CFDR单独选用 `"metrics":["CFDR"]`，输入 `counts.critical_faults` 与 `counts.detected_critical_faults`。

<!-- PDF第6页 -->
### 7.3 平均时间

```json
{"mode": "mean_time", "metric": "MTTD", "total_time": 240, "event_count": 12, "time_unit": "min"}
```

结果：MTTD=20min。若改为MTBFA，`total_time` 必须改用规定条件下的产品累计运行时间，`event_count` 必须改为已确认的虚警总次数；MTBFACF则使用显示或报告严重故障的确认虚警总次数。

### 7.4 相关性矩阵预计FDR

```json
{
  "mode": "correlation_prediction",
  "metrics": ["FDR"],
  "failure_rate_unit": "1/h",
  "faults": [
    {"id": "f1", "failure_rate": 0.002},
    {"id": "f2", "failure_rate": 0.001},
    {"id": "f3", "failure_rate": 0.001}
  ],
  "tests": ["t1", "t2"],
  "matrix": [[1, 0], [1, 1], [0, 0]]
}
```

矩阵行按 `faults` 顺序，列按 `tests` 顺序。1表示对应测试可观测对应故障，0表示不能；布尔值也可使用。非空测试集的模式作为可测故障集合，以上结果为75%。所有故障率必须使用相同单位，所有测试必须属于同一确认检测资源范围。

该模式只计算FDR。不同故障具有不同测试集不自动证明满足指定可更换单元层次与模糊度的FIR要求；多故障、间歇故障、非理想测试和不确定关联也未建模。需要FIR时，先按项目认可的方法完成隔离分类，再使用7.1的加权输入。
