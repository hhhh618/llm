## 三类工作必须分别立项、分别说明证据

| 项目 | 对象与主要证据 | 关键限制 |
| --- | --- | --- |
| 401 测试性试验 | 在产品实物上注入/模拟故障，实际检测隔离 | 适用于研制试验及性能鉴定期间的鉴定试验；预计/仿真不是实物试验结果 |
| 402 测试性分析评价 | 综合试运行、试验、演示、实物检查、相似产品、建模仿真等资料 | 对不能开展试验的产品或试验不能考核的要求使用；应说明不能试验/不能考核的具体范围 |
| 403 测试性评估 | 装备及配套产品实际运行、使用和维修数据，必要时补充试验等 | 贯穿状态鉴定、作战试验、综合评估、在役考核及使用期；统计口径和置信结论需明确 |

同一装备可能同时需要三项工作。可综合引用资料，但应记录资料来源、技术状态、用途与结论边界；不能把“某些故障不可注入”自动扩大为整个产品免试，也不能用测试性设计预计达标直接宣告使用评估达标。

### 资料性总指南：范围、条件与验证方案（A.7.1.1—A.7.1.5，PDF 54—55）

试验与评价用于确认设计有效性和水平、发现缺陷并改进、考核规定要求，以及评价诊断/测试保障资源。研制试验是增长管理的一部分，开展过试验并不保证产品已达到要求。

订购方应根据任务、产品种类和费用确定工作要求，把范围、层次、规划/方案等详细写入合同或技术协议；应提供使用条件与约束，至少包含定性/定量要求、试验环境、测试保障、使用模式和验证手段。每个产品的测试性试验都应有验证方案及大纲，试验后应形成报告。

## 401 测试性试验（8.1）

**目的与角色。** 确认设计有效性、评估测试性水平、发现设计与要求偏离；考核规定要求，为鉴定定型提供依据。试验组织部门、承试单位及研制单位的详细分工见下面资料性阶段指南；承制方/转承制方负责对试验问题改进并回归确认。

**输入（8.1.3，PDF 23）。** 测试性试验任务书或试验方案。编制提示：缺少任务书时可先编制方案草案，正式结论仍基于确定的要求、试验状态和评审后的大纲。

**正文要求（8.1.2.1—8.1.2.5，PDF 23）。**

- 应在产品实物上采用故障注入或模拟故障；适用于工程研制的研制试验及性能鉴定期间的鉴定试验。
- 应参照 GJB 8895，或按试验鉴定管理部门/组织方规定的要求开展；软件类产品还应参照 GJB/Z 141。未提供被引用标准时，不补造其抽样、允许失效数或置信算法。
- 可用共用或专用试验件；共用件应避免不同试验相互影响。研制试验可与功能性能试验结合或独立开展；鉴定试验件应达到规定的状态鉴定技术状态。
- 试验前应制定并评审大纲；完成后应编写报告并给出试验结论。
- 承制方/转承制方应改进试验发现的问题，并通过回归试验确认效果，不能只提交改进承诺或分析说明。

**输出（8.1.4，PDF 23）。** 试验大纲、试验程序、试验报告、试验问题分析及总结报告等。

**合同注意点（8.1.5，PDF 23）。** 一般应明确试验项目及提交文件资料。

### 401 资料性指南：五阶段实施（A.7.2.1.1—A.7.2.1.6，PDF 55—56）

| 阶段 | 主要负责方 | 关键工作与交付内容 |
| --- | --- | --- |
| 策划 | 试验组织部门 | 制定方案（项目、任务分配、进度、经费）；制定规范/要求（时机、试验件状态、设备、实验室与试验环境、阶段实施要求）；编制统计设计及注入操作指南（样本量、抽样、评估，注入适用场景与流程） |
| 设计 | 承试单位 | 确定输入和故障总体；设计统计方案；建备选故障样本库；编制试验大纲 |
| 准备 | 承试部门，研制单位配合 | 准备产品和工作环境，研制非标/注入设备、校准测试设备、搭建调试系统；编制用例与顺序 |
| 实施 | 承试部门负责，研制部门参与配合 | 按程序和详细步骤执行用例；按大纲监测、记录过程及问题处理结果 |
| 报告 | 承试部门 | 整理、分析、确认、汇总数据，评估指标，出具报告和结论；研制单位对设计缺陷分析并落实改进 |

**设计阶段不能漏的内容（A.7.2.1.3）。**

- 故障总体以受试产品 FMECA/FMEA 和同类/相似产品外场已发故障为输入，结合特点及测试性设计对象确定范围，保证模式完整与有效；先定义总体再抽样，不能用“能方便注入的模式”倒推总体。
- 以定量指标要求及故障总体按 GJB 8895 或组织方方法设计统计方案，确定本次样本量和抽样结果。
- 根据抽样结果，对特定检测方式的样本逐项设计注入方法；根据设计、故障特点及测试性方案定义注入成功判据和预期检测指示，建立备选库。
- 大纲应覆盖目的、产品组成/功能/要求、试验件及状态、环境与条件、完好/检测成功/隔离成功判据、统计方案、备选库、监测记录、组织管理、质量保证和技术安全措施。

**准备与报告细节（A.7.2.1.4、A.7.2.1.6）。** 用例需有编号、故障样本、判据、注入方法及条件信息；顺序应综合注入难易和对产品的影响。报告需说明依据、产品、设备环境、组织管理、实施经过、数据处理确认、指标评估、设计缺陷及优化建议。

### 401 资料性指南：试验类型、特殊样本与回归（A.7.2.1.7—A.7.2.1.11）

应事先考虑自然发生故障、虚警的处理，以及不可注入样本检测/隔离结果的确认方法。这些事件应按经确定的规则分类，不能不加说明地删去失败或不利样本。

**研制试验**以发现缺陷和增长为目标，并初步评估指标；原则上故障诊断样本集应覆盖全部功能故障模式。可由承制方组织，也可由订购方统一组织，属于研发试验；承制方应及早规划方案、规范及指南。

**鉴定试验**用于考核规定要求，属于性能鉴定试验；通常由试验鉴定管理部门组织并指定机构，承制方/转承制方配合。

可多轮开展：首轮摸底 → 针对缺陷改进并落实到实物 → 回归确认效果 → 再组织鉴定试验。研制摸底和鉴定验收应说明不同目的及技术状态。

回归证据宜记录问题标识、原失败条件、原因、改进版本、受影响用例、回归数据与效果结论，并关联产品实物状态。这是本资源的执行建议；正文强制点是**改进后进行回归试验确认**，不能以“预计变好”代替。

## 402 测试性分析评价（8.2）

**目的与角色。** 综合利用相关信息评价是否满足规定要求；一般由试验鉴定管理部门指定机构开展，承制方/转承制方配合。

**输入（8.2.3，PDF 24）。** 测试性分析评价任务书或方案。

**正文要求（8.2.2.1—8.2.2.5，PDF 23—24）。**

- 不能开展测试性试验的产品，以及试验不能考核的测试性要求，应用分析评价方法进行鉴定。明确是产品范围还是具体要求范围。
- 应综合采用产品及组成部分的试运行、测试性试验、功能演示、实物检查、相似产品数据，或建模/仿真资料等，在状态鉴定前完成。
- 开展前应制定并评审大纲；完成后应编写报告及评价结论。
- 承制方/转承制方应改进发现的问题，并确认改进有效性。该条要求有效性确认，不能混写成 401 专门规定的实物回归试验；实际确认方法应与问题和评价证据相适应。

**输出（8.2.4，PDF 24）。** 分析评价大纲、报告、问题分析及总结报告等。

**合同注意点（8.2.5，PDF 24）。** 一般应明确分析评价项目及提交资料。

### 402 资料性指南：替代同意、证据与审定（A.7.2.2.1—A.7.2.2.4）

对未能进行鉴定试验的产品和要求，经订购方同意可用分析评价替代鉴定试验。方法、数据、评价准则和结果均应获订购方认可，完成报告应经订购方审定。

可使用研制试验、试运行、核查资料、低层产品试验数据综合、同类水平比较、仿真/虚拟样机、设计缺陷分析等方法；复杂系统应说明低层数据如何组合、边界和接口故障是否覆盖，相似数据应说明差异及适用性。设计定型的分析结果可为使用期评价提供支持信息，不因有此结果就省去 403 的实际数据要求。

宜逐条建立“待鉴定要求—不能试验理由/范围—替代方法—证据来源及状态—准则—结果—不确定性—订购方确认”表，并单列未被任何证据覆盖的要求。表是编制建议，确认事项来自上述指南。

## 403 测试性评估（8.3）

**目的。** 收集信息，评估装备是否满足规定测试性要求，面向达到的实际水平。

**阶段、组织和结论用途（8.3.2.1—8.3.2.5，PDF 24）。**

| 场景 | 正文规定的组织/工作 | 用途 |
| --- | --- | --- |
| 状态鉴定性能试验期间 | 应针对研制总要求中的测试性要求开展鉴定评估；一般由管理部门指定机构，利用实际运行数据，必要时补试验和分析评价数据 | 状态鉴定、列装定型 |
| 作战试验期间 | 作战试验部队应同步收集信息，在近似实战环境及对抗状态评估要求满足情况与缺陷 | 列装定型 |
| 作战试验结束后 | 管理部门建立的专项工作组应按需要汇总四类结果：测试性试验、分析评价、性能鉴定期间评估、作战试验评估；确认实际数据中的故障、检测、隔离、虚警、时间 | 综合评估、列装定型 |
| 在役考核期间 | 承试单位应同步收集信息，评估考核状态下的水平和达标情况 | 在役状态评估 |
| 使用期间 | 应持续收集信息并评估使用条件下水平 | 改进测试性、使用与维修、新装备论证 |

**输入（8.3.3，PDF 25）。** 鉴定定型试验总案；状态鉴定性能试验大纲；作战试验大纲；测试性要求；使用运行/试验/测试数据或评估需求。

**正文要求（8.3.2.6—8.3.2.10，PDF 24—25）。**

- 应使用装备及配套产品实际使用、维修等数据；不足时可补充试验等综合评估，补充数据应保持来源可追溯，不能冒称自然运行样本。
- 定量达标评估：FDR、FIR、平均虚警间隔时间一般采用**单侧置信下限**；虚警率一般采用**单侧置信上限**。点估计值好于门限，不等于置信限已满足门限。
- 定性要求应结合使用维护，以演示、实物检查、资料审查等方式逐条确认。
- 评估前应编制大纲，明确依据、目的、对象/技术状态、定量定性要求、周期、数据范围、判别与统计筛选原则、定量模型及定性方法；大纲应经评审和批准。评估后应编写报告。

**输出（8.3.4，PDF 25）。** 评估大纲、评估报告。

**合同注意点（8.3.5，PDF 25）。** 应明确数据/方法要求及信息收集协调；评估应尽可能与可靠性、维修性、保障性、安全性评估结合。

### 403 资料性指南：阶段衔接与数据确认（A.7.2.3.1—A.7.2.3.8，PDF 56—57）

状态鉴定评估应在鉴定试验和分析评价基础上全面考核要求；作战后可按需要汇总各阶段数据作综合评估，使用期仍应继续收集和评估。附录在作战试验、综合评估、在役考核方面使用“可”；正文 8.3 对相应情境明确“应”或“应根据需要”，实施路由以正文为准，不能利用资料指南措辞弱化正文。

评估应采用实际使用数据，不足时可用试验数据补充；工作应由试验鉴定管理部门建立的相应工作组开展，并确认故障、检测、隔离、虚警及时间数据。使用期的持续信息收集和改进详见本技能的使用期资源。

### 403 资料性指南：样本、置信限与不足处理（A.7.2.3.9—A.7.2.3.13）

**不同参数使用不同样本总体。**

| 参数 | 指南要求确认/统计的依据 |
| --- | --- |
| FDR | 发生的责任故障次数；原始记录确认规定手段能检测且报警的，判正确检测 |
| FIR | 能被正确检测的故障次数；原始记录确认报警满足规定隔离模糊度的，判正确隔离 |
| 虚警率 | 报警次数；依原始报警记录及相关工作确认没有故障的，判虚警 |
| 平均虚警间隔时间 | 虚警次数以及产品运行时间 |

责任故障、正确检测、正确隔离、报警与虚警应按大纲定义和筛选规则确认。不能把全部故障作 FIR 分母、把故障次数作虚警率分母，或把未复现/CND 自动等同于已证实无故障。每条记录保留原始证据与分类依据。

**估计方式（A.7.2.3.10）。** FDR、FIR、平均虚警间隔时间采用单侧置信下限，虚警率用单侧置信上限。当 FDR/FIR 要求值为 **100%** 时，可采用点估计；其他时间类参数可采用点估计。这个 100% 例外来自资料性指南，使用时在批准大纲中明确依据，不把它扩展到其他指标或任意目标值。

报告宜同时写样本量、成功/失败/虚警数或运行时长、点估计、单侧置信限、置信水平、门限、采用的方法及判定。置信水平和统计方案取自已确定要求/大纲，不能自行默认为 95%。计算与零事件边界处理见 [指标与计算](07-指标与计算.md)。

**最小样本量（A.7.2.3.11）。** 指南将其定义为“定数最低可接受值试验方案中合格判定数等于零时”的样本量。FDR、FIR、虚警率统计样本低于最低量时，具备条件的应补充必要故障注入试验；不具备条件的应注明样本不足。不能虚构统一最低样本数，也不能隐去“不足”后直接输出充分验证达标的结论。

**定性与文档（A.7.2.3.12—A.7.2.3.13）。** 定性要求应逐条判别并给出说明。评估前后应分别有大纲和报告；作战试验及在役考核可将其并入装备级大纲/报告，仍应保留测试性内容和依据。

## 交付检查：结论与证据相匹配

以下是本资源的编制检查表，依据正文 8.1.2.4—8.1.2.5、8.2.2.4—8.2.2.5、8.3.2.6—8.3.2.10 及 A.7 的指南整理，不增加标准规定的验收门限。

- **任务路由可解释：** 实物试验、不能试验的分析评价、实际运行评估的范围明确；适用要求逐条覆盖。
- **基线可追溯：** 对象、硬软件状态、测试手段、维修级别、层次及隔离模糊度一致；补充数据及技术状态差异明确。
- **大纲程序完备：** 401/402 大纲经过评审，403 大纲经过评审和批准；401 有执行程序及用例证据。
- **统计判据先定：** 故障总体、抽样、数据筛选、样本最低量、估计方式、置信水平和门限有依据；自然故障、虚警、不可注入故障的处置可核对。
- **问题闭环成立：** 401 有实物改进与回归证据；402 有有效性确认；各类未关闭问题、证据不足及结论限制如实记录。
- **组织确认齐全：** 负责方与配合方清楚，402 替代/方法/数据/准则/结果的订购方确认可追溯，403 实际数据经过确认。
- **报告给出限定结论：** 定性逐条说明；定量区分点估计与单侧置信限，显示样本不足，说明证据支持的状态与适用环境。
