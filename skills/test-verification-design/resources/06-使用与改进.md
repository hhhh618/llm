## 1. 501：使用期间测试性信息收集（正文9.1）

**目的：** 有计划地收集使用期间数据，支持使用测试性评估与改进，并反馈新研装备论证和研制。（9.1.1）  
**责任：** 装备使用单位组织收集计划并按计划执行；全寿命数据责任方面，使用阶段由装备订购方负责。（9.1.2.2~9.1.2.3；6.5.2.1，PDF16）

**正文要点：**

1. 在205已有数据工作的基础上，覆盖使用、维修、贮存、运输过程中产生的测试性信息。（9.1.2.1）
2. 在201的基础上，使用单位应制定信息收集计划，明确：收集／分析部门及人员职责；管理监督与保密要求；范围、方法、程序；分析处理传递要求及方法；分类方法；定期分类审核和汇总；向承制方反馈安排。（9.1.2.2）
3. 应按计划完整准确收集，按规定的方法、方式、内容、时限分析与存储，定期审核、汇总、上报、反馈。（9.1.2.3）
4. 信息应参照GJB 1775及有关标准分类编码，并纳入装备使用单位的信息系统。本资源未收录这些引用标准的完整编码规则。（9.1.2.4~9.1.2.5）

<!-- PDF第26页 -->
**输入：** 测试性计划；可靠性、维修性、保障性信息收集计划及工作要求；用户已有装备信息系统要求。（9.1.3，跨PDF25~26）  
**输出：** 使用期间测试性信息收集计划、按计划收集的使用期间测试性信息。（9.1.4）  
**注意：** 应结合可靠性、维修性、保障性信息收集；重视及时、真实、完整、准确；内容应足以支持评估测试性。（9.1.5）

## 2. 501的资料性信息指南（A.8.1、A.8.2.1）

501是502的基础和前提：采集范围与分析方法应考虑改进需求，利用信息共享和传递减少重复；信息管理纳入装备统一信息管理，改进与其他装备改进协调。还应建立信息收集与核实、分析与处理、传递与反馈的责任制度。（A.8.1.1~A.8.1.3、A.8.2.1.1，PDF57~58）

<!-- PDF第58页 -->
附录提示先分析评价及改进的信息需求，再决定范围、内容和程序。一般应覆盖：

| 数据类别 | 应保留的信息要素 |
| --- | --- |
| 已证实故障 | 测试环境／维修层次；BIT、ATE或人工方法；隔离产品层次与模糊度；信息显示及存储；BIT与ATE结果一致性 |
| 报警／指示但未证实故障 | 报警性质（虚警、CND等）、频度、原因、忽视报警后果；相关任务失败／降级／停机等维修和使用费用 |
| 使用缺陷 | 使用中发现的测试性缺陷 |
| 运行暴露量 | 系统累计运行时间 |
| 测试过程 | 测试用时间、费用、日期、测试单位 |

来源：A.8.2.1.2。应按GJB 1775等统一分类、信息单元及编码，建立通用数据库等；应组成专门小组，定期评审收集、分析、贮存和传递的有效性。（A.8.2.1.3~A.8.2.1.4）

**判别提醒（操作整理）：** “未证实”不是已确认虚警。应保留原始报警及确认依据；CND不能直接并入虚警统计。间歇故障和BIT自身问题都可能导致不能复现；FAR评估需按确认“没有发生故障”的报警判虚警。（A.4.2.1.10.2(g)，PDF34；A.7.2.3.9，PDF57；A.8.2.1.2，PDF58）

## 3. 502：使用期间测试性改进（正文9.2）

**目的：** 针对使用中暴露的测试性问题采取措施，提高装备测试性水平。（9.2.1）  
**责任：** 订购方在201、202基础上组织制定使用改进计划并组织实施；涉及承制方工作的要求应有合同依据。（9.2.2.2、9.2.5）  
**输入：** 使用中发现的测试性问题、在役考核期间测试性评估结果。（9.2.3）

**正文要点：**

1. 结合使用或在役考核发现的问题和技术发展，通过分析论证确定改进项目。（9.2.2.1）
2. 改进计划应包含项目、方案与目标；单位／人员及职责；改进后验证要求与方法；经费及进度。（9.2.2.2）
3. 改进途径可包括测试性设计、检测与使用方法、测试设备及保障系统，以及其他适用途径。（9.2.2.3）
4. 在实际使用过程中全面跟踪、评估改进措施有效性。（9.2.2.4）

**输出：** 使用期间测试性改进计划、改进方案、改进报告。（9.2.4）  
**注意：** 承制方承担的使用期间改进工作应在研制合同中明确；必要时可单独签订合同。（9.2.5）

## 4. 502的资料性实施指南（A.8.2.2）

- 改进项目应对使用安全、状态监测、减少维修耗时、降低维修难度或使用费用有重要作用；应通过必要分析或试验确定，并与其他改进充分权衡，保证总体效益。（A.8.2.2.1~A.8.2.2.2）
- 涉及产品测试性设计时，应与承制方协商方案，承制方应配合；方案应经评审并获得批准，之后由承担任务的单位实施，一般为原承制方。（A.8.2.2.3~A.8.2.2.4）
- 方法依据具体问题确定，包括调整检测门限／修正故障判别及诊断程序、改善维修检测及使用方法、改善测试设备及保障系统、以测试性较好的新产品替换问题产品等。此处没有通用的新门限数值，不能凭该例自定参数。（A.8.2.2.5）
- 实施方应提交完整设计文档和改进后的测试性试验验证报告。（A.8.2.2.6）

<!-- PDF第59页 -->
**资料性管理职责完整清单：** 专门组织应负责组织论证并确定项目、制定改进计划、组织项目及方案评审、跟踪改进过程、组织验证、编制改进项目报告等。前两项在PDF58，后四项续至PDF59；不可把最后一页误判为空白。（A.8.2.2.7(a~f)）

## 5. 205／403／206／501／502接口与阶段区分

| 工作 | 阶段与作用 | 接口与依据 |
| --- | --- | --- |
| 205 数据管理 | 研制、生产、使用全寿命阶段 | 承制方负责研制生产，订购方负责使用；提供设计、试验、原始诊断和维修数据（6.5.2.1~6.5.2.5，PDF16） |
| 403 测试性评估 | 性能鉴定、作战试验、在役考核及使用期间，按各阶段要求进行 | 实际使用数据为主，不足时可补试验数据；确认实际达到的测试性水平（8.3.2.1~8.3.2.6，PDF24） |
| 206 增长管理 | 研制初期起；综合处理研制、鉴定、作战、在役和使用发现的问题 | 分析原因、纠正、跟踪确认；使用问题在装备改进中解决（6.6.2.1~6.6.2.5，PDF17） |
| 501 信息收集 | 使用期间，包括使用、维修、贮存、运输 | 基于205／201形成有计划的数据，为403、502及新研论证提供支持（9.1.1~9.1.2，PDF25） |
| 502 使用改进 | 使用或在役考核发现的问题进入装备改进 | 基于201／202组织计划、方案、实施及有效性跟踪（9.2.2，PDF26） |

501不能替代403达标评估，502不能替代206的跨阶段增长管理。使用信息需反馈承制方及其设计／生产过程，双方交数的产品层次和资料要求由合同／协议明确。（6.5.5，PDF17；9.1.2.2(g)~9.1.2.3，PDF25）

## 6. 闭环操作清单（基于条款的执行整理）

1. **建计划并采集：** 依据201与205确定501的职责、范围、分类、程序、时限与反馈安排，保留证实故障和未证实报警的区分。（9.1，PDF25~26；A.8.2.1，PDF57~58）
2. **确认并评估：** 按403评估大纲确认技术状态、要求、数据范围、筛选原则、模型及定性方法；大纲应经评审批准。依统计方案处理置信限与样本不足，不能将采集数量或点估计直接当达标结论。（8.3.2.7~8.3.2.10，PDF24~25；A.7.2.3.9~A.7.2.3.11，PDF57；详见[05-试验与评价.md](05-试验与评价.md)）
3. **确定改进并组织实施：** 用使用问题、在役评估及相关分析提出502项目，明确目标、责任、验证、费用进度和合同依据；涉及设计的方案与承制方协调，按经认可的评审批准安排实施。（9.2，PDF26；资料性A.8.2.2.1~A.8.2.2.4，PDF58）
4. **验证并反馈：** 跟踪使用效果，保存设计文档、验证报告及改进报告，反馈205和206；原因、措施或验证依据未确认时，在问题记录中保留未决状态，不能声称闭环完成。（9.2.2.4、9.2.4，PDF26；6.6.2，PDF17；资料性A.8.2.2.6~A.8.2.2.7，PDF58~59；见[03-测试性管理.md](03-测试性管理.md)）

**输出建议：** 每个改进条目列出问题及原始记录、装备／产品技术状态、相关要求与条款、原因分析、方案、负责人、经费进度、评审批准状态、验证方法和证据、使用跟踪结果、剩余问题。此字段组合为技能操作模板，不是标准原列的单一固定表格。
